# Native process identity

`win32-process.c` uses the stable Node-API C interface and documented Windows APIs from `kernel32` and `advapi32`. It returns a process's creation FILETIME as a decimal string and this account's SID from its token. For process custody it starts one program per process inside a new job object. The job kills every member when its last handle closes and allows no breakaway. `CreateProcessW` assigns the job at creation through `PROC_THREAD_ATTRIBUTE_JOB_LIST`, so no child starts outside it. It passes the child only its input and log handles through `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`, so no member can hold the job open. The binding then lists the job's processes, reads the program's exit code and terminates the job. It has no runtime dependency or PowerShell fallback. `win32-system-id.cpp` reads the system ID Windows documents for an unpackaged app's publisher, through C++/WinRT's `SystemIdentification.GetSystemIdForPublisher`, and the module Windows derived it from. It is C++20 and links `windowsapp.lib`; the binding reports the ID and its source, and a caller refuses a source of none.

`darwin-process.c` uses the same interface and the documented macOS kernel interfaces. `sysctl` with `KERN_PROC_PID` gives a process's start time in microseconds, its process group and whether it is stopped. `KERN_PROC_PGRP` lists the members of a process group. `gethostuuid` gives the machine's UUID and `kern.bootsessionuuid` gives this boot's UUID. It does not use `libproc`, whose header calls its interfaces private and subject to change, and it never runs `ps`.

Build on native Windows x64 and arm64 in the matching MSVC Developer Command Prompt, or on macOS x64 and arm64 with Xcode or its command line tools, with `pnpm --filter @cotal-ai/workspace build:native`. The script downloads only the checksum-pinned Node headers in `node-sdk.json`, and on Windows the import library. On Windows it takes the C++/WinRT headers from the Windows SDK the prompt selects. A macOS bundle targets macOS 11.0, the oldest macOS Node 22 supports, and resolves Node-API symbols from the loading `node`. The script records source, SDK, compiler and binary provenance beside the output. An existing binary must verify before reuse; stale output is an error.

Both Windows and both macOS architecture directories and their receipts must be assembled under `build/Release` before packing or publishing workspace; the shared native workflow builds the macOS pair on `macos-15-intel` and `macos-15` when a caller asks for it with `darwin: true`. Customer installation uses these prebuilt files and runs no compiler or native download. The Windows identity CI suite runs the same Node-API 8 binaries on Node 22, 24 and 26 on x64 and arm64 runners. Its PowerShell compatibility oracle is test-only and runs after the first cold production read. `smoke/darwin-process-native.smoke.ts` runs the macOS binding on a macOS runner under Node 22, and `smoke/win32-job-native.smoke.ts` runs the Windows job custody on a Windows runner. `smoke/win32-custody.smoke.ts` checks the custodian handshake on every platform and runs the custodian itself on Windows.
