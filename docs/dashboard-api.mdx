Source: [OpenAPI description](../implementations/web/openapi.json).

HTTP interface of the @cotal-ai/web reference implementation. This description covers read operations, readiness metadata and the legacy channel deletion route; it does not establish a separate stable product or Cloud management API. Start the dashboard using the web service preset described in the operator guide. The server defaults to 127.0.0.1:7799; use the host and port configured for your dashboard.

Open the owner-private launch URL once to exchange its k query token for the cotal_web_session cookie. Keep the session on the same host. With the default bind, the permitted browser origins are [http://127.0.0.1](http://127.0.0.1):\<port>, [http://localhost](http://localhost):\<port> and [http://cotal.localhost](http://cotal.localhost):\<port>. A custom host uses its own HTTP origin. A cross-origin request is refused before session checks. The readiness nonce only opens /api/meta.

Read operations use GET and take no request body. Some read handlers also accept other bodyless methods; this description does not promise a 405 response for them. The native web service is read-only and always refuses channel deletion with 403. Legacy direct dashboard instances can enable deletion; /api/meta reports channelDeleteSupported. Description version 1 identifies this document, not the wire or npm package version.

## Reading the contract

The [interactive reference](https://docs.cotal.ai/api/dashboard/) and [downloadable OpenAPI specification](https://docs.cotal.ai/dashboard.openapi.json) describe the same operations.

## Watch live dashboard events [#watch-feed]

```http
GET /feed
```

Open a Server-Sent Events stream. Each frame has event: \<name> and data: \<JSON>, followed by a blank line. The initial frames contain roster and presence-view, then membership or membership-read-failed. Later frames carry roster, presence-view, membership, membership-read-failed and message updates. The stream provides no event IDs or replay cursor; reconnect and read history for backfill. An unhandled request failure after headers have been sent closes the stream. Membership read failures are sent as events and leave the stream open. The schemas under x-sse-events describe decoded data payloads.

| Event                    | JSON data                                                                            |
| ------------------------ | ------------------------------------------------------------------------------------ |
| `roster`                 | Array of presence records, with optional dashboard progress.                         |
| `presence-view`          | `state` and `fresh`, plus `staleSince` for a stale observer.                         |
| `membership`             | Optional `asOf` and an array of `members` with live and durable channels.            |
| `membership-read-failed` | An object with a `reason` string.                                                    |
| `message`                | `mode` and `msg`, with subject-derived `senderId` and chat `channel` when available. |

Decoded payload schemas are also included under `x-sse-events` in the [downloadable specification](https://docs.cotal.ai/dashboard.openapi.json).

The message event forwards publisher JSON without wire-message validation. Treat msg.from as advisory; senderId is derived from the broker subject. A malformed publisher payload can still appear in the feed.

## Delete a legacy dashboard channel [#delete-dashboard-channel]


## Watch an agent's event frames on a feed [#watch-agent]

```http
POST /api/agents/{agent}/watch
```

Subscribe one open feed to the agent's event-plane frames, which then arrive on that feed as agent-frame events. No body: a watch is a row in this process's map, which the feed's close removes. It changes no mesh state. Watching again is still 204. Other methods fall through to 404.

## Post as the operator [#send-as-operator]

```http
POST /api/send
```

Post one message as the operator the process holds: \{kind: "msg", channel, text} to one concrete channel, or \{kind: "dm", to, text} to one roster member. The body is read before any refusal, so the 8192-byte cap bounds what a refused post costs, and every check runs before the poster starts, so a refused post never puts the operator on the roster. A wildcard or alias channel, an id not on the roster, an empty text, another kind, or a body that is not a JSON object is refused with 400. A read-only service, an expired operator credential and a cross-origin request answer 403 with the reason. A publish the broker refuses answers 502 with the refusal. Other methods fall through to 404.

### Parameters

No operation parameters.

### Request body

The request uses the schema below.

Required: yes.

Content type: `application/json`.

```json
{
  "type": "object",
  "properties": {
    "kind": {
      "type": "string",
      "enum": [
        "msg",
        "dm"
      ]
    },
    "channel": {
      "type": "string",
      "minLength": 1,
      "description": "The channel, for kind msg. One concrete channel; no wildcard."
    },
    "to": {
      "type": "string",
      "minLength": 1,
      "description": "The roster member's agent id, for kind dm."
    },
    "text": {
      "type": "string",
      "minLength": 1,
      "description": "The message. Trimmed; an empty text is refused."
    }
  },
  "required": [
    "kind",
    "text"
  ]
}
```

Example: channel

```json
{
  "kind": "msg",
  "channel": "general",
  "text": "Ship it."
}
```

Example: dm

```json
{
  "kind": "dm",
```
