Start, inspect, and stop a local mesh from a prepared project.
If this is your first run, complete the [Quickstart](getting-started.mdx).
Use [Configure a space](setup.mdx) to prepare another project or change its defaults.

## The stack [#the-stack]

`cotal up` starts these local components:

- A NATS broker. Its log is `.cotal/nats.log`.
- A delivery daemon in authenticated mode. It provides [durable delivery](delivery-daemon.md).
- A manager. It handles detached agents and the `cotal_spawn` tool.

Authentication is enabled by default.
The broker authenticates senders and checks each agent's permissions.
The broker and local services bind to loopback, so other machines cannot connect through that listener.
If the default broker address is occupied by another project, Cotal chooses a free local port.
An explicit `--server` fails on a collision.

Cotal requires nats-server 2.12 or newer.
Older spaces with a file-backed presence bucket need 2.14.5 or newer to avoid a known write failure.
Current spaces use memory-backed presence.
See [Recover stuck presence](recover-a-mesh.mdx#presence-write-stuck) before reusing an older broker or store.

## Start the local stack

From the prepared project folder, run:

```bash
cotal up --detach
```

This starts the stack in the background and reports the selected space and mesh address.
Background startup is also the default for bare `cotal up`.
For a terminal or service manager that must own the stack's lifetime, use `cotal up --foreground`.
See [Supervise the stack](supervise-processes.mdx) before creating a systemd unit.

Static authentication is the default.
For per-user authentication, use `--user-auth --idp <url>` and follow [Identity](identity-and-auth.md).
This also starts the space's auth service. Participants log in, and the operator grants their agents on the actor ledger.
The `--open` mode is unauthenticated and live-only. It has no delivery daemon.
Use that mode only for local development experiments.

## Check the stack

Run:

```bash
cotal status
cotal status --components
```

The status report shows setup, local processes, registered meshes, and live mesh state.
Its Machine section identifies the running installation and version.
Check the connector rows before launching an agent.

The component check distinguishes absent processes, components that are not serving, and refused requests.
Follow the report's next action if the stack is incomplete.
[Recover a mesh](recover-a-mesh.mdx) explains the project logs and recovery states.
[Launch agents](launch-agents.mdx#check-connector-availability) explains how the manager checks installed connectors.

## Stop the stack

<Callout type="warn" title="Check agent lifetime before stopping">

The built-in `pty` runtime runs its seats inside the manager process.
Those seats stop and are deprovisioned whenever the manager stops, including bare `cotal down`.
Other managed agents stay running as unmanaged OS processes unless you pass `--with-agents`.

</Callout>

To stop the stack, run:

```bash
cotal down
```

A current manager records whether it can leave its seats running before shutdown.
If that stop is refused, the manager, broker, delivery daemon, and any auth service remain running.
For example, a manager can refuse when it cannot prove that it can spare its agents.

To stop the stack and deprovision its managed agents, run:

```bash
cotal down --with-agents
```

An older manager may not publish that capability record or understand the reap request.
Cotal prints a reduced-guarantee warning before signalling a pre-pin legacy manager.
Its older SIGTERM handler may still reap agents, so a pre-stop inventory does not prove those agents survived.
Stop an older manager's managed agents explicitly before whole-stack shutdown when its capability record is absent.

On POSIX, a foreground broker has its own session and process group.
Ctrl-C reaches the CLI owner first, which uses the same stop procedure and report as bare `cotal down`.
A refused stop leaves the stack running. Use `cotal down --with-agents` when you intend to stop its agents too.

## Watching [#watching]

`cotal console` opens the terminal view. It prints a line stream when piped.
The separately configured web service provides the browser dashboard.
Both observe the mesh without starting dependencies.
Follow [Watch a mesh](watch-a-mesh.mdx) for either view.

## History [#history]

<Callout type="warn" title="History deletion is permanent">

Retained history is operator-owned.
`cotal clean history --force` purges a space's retained channel history.
Add `--dms` to purge DMs too. `cotal history clear` is an alias.
These are operator commands. Agents have no tool that wipes the record.

For a stopped mesh, `cotal clean store --force` deletes its on-disk JetStream store.
`cotal clean all --force` also resets the space identity.
Read the [cleanup reference](cli.md#clean) before running either command.

</Callout>
