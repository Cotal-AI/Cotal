# Hosted runtime contracts

Status: proposed implementation contract. This is not a shipped pooled runtime or a wire change. The source inventory below was checked at `6b7694671fffcde331c3676b267cd0d2b3c523b2`. [The machine-readable interface and ownership record](hosted-runtime-ownership.json) assigns the follow-on work. A worker must still test the exact head it implements.

## Narrow interfaces for implementers

Use the existing `SecretStore`, `SecretStoreIdentity`, `RemoteManagerAuthorityRequest`, `ManagerOptions.remoteAuthority`, `EpServeGrant` and `RunHostLease` rather than duplicating them. `@cotal-ai/workspace` exports the provider-neutral `HostedContextInputs`, `HostedContextKey`, `HostedServiceState` and `HostedServiceHandle` types. No service implements the handle yet. The types describe explicit context inputs and lifecycle outputs:

```ts
type HostedContextInputs = {
  context: { accountPublicKey: string; lifecycleUid: string };
  space: string;
  servers: string;
  store: SecretStore;
  storeIdentity: SecretStoreIdentity;
  stateDir: string;
};
type HostedServiceHandle = {
  readiness(): HostedServiceState | Promise<HostedServiceState>;
  drain(): Promise<void>; // close admission, finish only bounded accepted work
  close(): Promise<void>; // idempotent; release only owned resources
};
```

The authority and delivery instances accept explicit space/account, broker transport, store with stable identity and state paths at construction. `start` returns a handle only after startup gates. No service instance changes cwd, installs signal handlers, calls `process.exit`, reads an implicit global secret, or imports unused execution connectors. Wrappers own signals/exits. A sibling remains ready after one context closes.

A standing-bundle request extends the **closed** manager-service-authority family with the authenticated owner, assigned account, registered `instanceId`, manager lifecycle, current serve `processEpoch` and registration proof. The issuer derives all five profiles, grants and TTLs server-side. It returns one bounded set of supervisor, executor, serve, goal-writer and session-ledger JWTs for the **same** caller-held nkeys, with exact request/epoch echoes and no signer seed. The caller validates all echoes, preflights the candidate set, stages it through the existing credential-family and serve gates, and adopts it atomically before reconnecting holders. A partial or unproven candidate never clobbers last-good. Retrying the same operation id must not revoke active credentials; unresolved cleanup debt refuses new issuance. `renewExecutor` remains compatible with the stock CLI.

A run-driver request is a separate closed operation under that family. It binds the authenticated caller, account, `instanceId`, runId, holder, takeoverId, epoch and fencingToken from the current activated run. Only the issuer chooses the run-driver and run-mediator profiles/TTLs. The response names those same coordinates and nkeys; a superseded attempt or another run is refused. A renewed JWT alone does not move a journal activation or override mediated-effect fences.

The control `instanceId` is persisted by the assignment writer and reused by successors. Each new process must pass the current epgate owner/lifecycle/processEpoch before serving. Manager liveness is not a goal or run write fence. Goals use the accepted-goal journal and serve epoch; sessions use session epoch/expiry; runs use `RunHostLease` and mediated activation; delivery uses its own lease; auth mint/callout refuse immediately on plane fence. A taken or unknown pooled control lease is unavailable, not stock's indefinite serving retry.

## Assignment, isolation and restart

The backend is the only writer of `{ accountPublicKey, cellId, groupId, slotId, controlInstanceId, assignmentRevision }`. An atomically rendered durable per-cell slot manifest carries those fields and the stable, nonsecret store coordinate. On restart, a worker validates the entire manifest against the injected store/account view before touching the broker; a missing, partial, mismatched, or stale same-slug account is unavailable. Assignment revision and account key index every cache, queue and cancellation key. A manifest is placement evidence, never mint authority. Before a handoff, stop admission, commit the mapping and render both manifests, drain bounded work, wait for absent/expired ownership and advance each duty's own fence. An old holder reconnecting afterward must fail its next effect.

Only two worker roles exist. An authority slot holds at most **16** assigned account signers under its group uid/view; a context slot has its own distinct uid/view, no signer or root seed, and only enumerated account-scoped credentials through an authority-local peer-uid-checked adapter. That adapter checks the actual peer uid, account key, store identity and allowed kind, denies enumeration/writes, and preserves mode 0600. A group view cannot read another group's signer. Broker operator and `$SYS` signers stay with privileged rotation. Observer and evictor credentials may be read only in the assigned context; their refresh stays with that rotation path. Raw KICK privilege remains a shared-cell availability residual, not tenant isolation. Pooled control accepts a hosted sandbox or authenticated participant manager, never local PTY custody.

One slot supervisor owns per-context restart: on a context failure it closes that context's connections, reports `unavailable` with cause, then retries stock claim/registration gates with capped jitter and a bounded queue. Expected contention does not kill siblings. A failed authority fence/close, corrupt supervisor or repeatedly fatal restart exits the slot for systemd. A worker-wide event-loop stall is a group failure, not independent per-context availability. Set transport `pingInterval=5s`, `maxPingOut=2`; test scheduled-loop detection within 15 seconds. This measures transport, not authority/readiness. A single lag meter serves each worker; bounded queues refuse excess work visibly. Capacity below the 16-account trust ceiling and per-role/agent/queue limits come from native measured fixtures, not invented constants.

In the hosted composition, the backend owns assignment and cell mapping, systemd owns uid/view projection and process restart, the authority owns signing/adapter/renewal, and the context owns delivery/control effects. The existing stream/lease/epoch and terminal barriers remain the write authority. Preserve `/mesh-ws` for the first cell and advertise distinct same-origin routes for added cells; routing cannot select a foreign account from caller input. Neither the manifest nor this guide grants a worker a database writer or a generic signing endpoint.

## Native proof required before activation

Each worker records exact case enumeration, attempted counts and positive/negative outcomes. Test two accounts (including identical actor names), each cell and same-slug account recreation; wrong cell, slot, store identity, uid/kind, assignment revision, stale epoch and old-holder reconnect must refuse while a sibling succeeds. Exercise expired delivery creds and a dead predecessor through signer preflight, delivery oracle and auth-plane claim in that order, including lost reply. Kill/partition each duty during renewal, accepted goal, timer, run, retirement and handoff; assert no dual owner or second accepted operation. Run zero-agent expiry and failed-then-repaired renewal through **every** standing and run credential on real connections. Assert bounded queues/readiness and immediate fenced mint refusal. Test effective filesystem uid boundaries and pooled PTY refusal, with named reverted-code mutations that fail their intended assertions. Record source, typecheck/build, native behavior and mutation evidence separately. A broker-free or unrun suite is not this gate.
