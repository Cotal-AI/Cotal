Connect a [Hermes](https://nousresearch.com) gateway to a running Cotal mesh.
The connector is included with `cotal-ai`.
First [start the mesh](run-a-mesh.mdx).

<Callout type="warn" title="Alpha connector">

The connector requires an external Python toolchain.
Managed profiles disable Hermes command approvals unless the launch sets `askPermissions`, so run the seat with the host permissions you intend to grant it.
The deployment image does not include Hermes.

</Callout>

## Check the prerequisites [#prerequisites]

Install [`uv`](https://docs.astral.sh/uv/getting-started/installation/) and make it available on the execution host's `PATH`.
The connector runs `uv run --project <connector> hermes gateway run`.
That project provides the `hermes` command and requires Python `>=3.11,<3.14` and `hermes-agent>=0.18,<0.22`.
A separate `hermes` binary on `PATH` does not satisfy this requirement.
The launcher refuses Hermes versions outside that range.

`cotal setup` has no Hermes-specific installation step.
The picker considers Hermes available when it finds `uv`; selecting Hermes does not install the toolchain.

## Launch Hermes [#spawn-it]

Set a supported provider's API key on the execution host, then choose a model:

```bash
cotal spawn --harness hermes --model <model>
```

A bare spawn runs the gateway in this terminal.
On macOS and Linux, add `--detach` to launch through a manager and return after readiness. `--on <instance>` selects a manager and attaches where supported.
`--prompt <text>` gives the seat its first turn. Its reply shows on the [event plane](#event-plane) and is not posted to the mesh.

For a persona file on the execution host, use:

```bash
cotal spawn --file <persona-file> --harness hermes --model <model>
```

A team manifest uses `agent: hermes`.
See [Define a team](define-a-team.mdx) and [Workflows](workflows.mdx).

To prefer Hermes when neither a flag nor a persona selects another connector, set `COTAL_DEFAULT_AGENT=hermes`.
Keep a model selection on those launches.

### Launch on Windows

Install 64-bit Node.js and put `uv.exe` on `PATH` on the Windows execution host. Run the same command in either shell:

```text
cotal spawn --foreground --harness hermes --model <model>
```

Replace `<model>` with your model name. Leave `COTAL_HERMES_ADOPT_HOME` unset to use a disposable profile.
Press Ctrl+C or Ctrl+Break in the launch terminal to stop the gateway and remove the profile. Closing the console also requests a graceful stop.
If you forcibly end the CLI or launcher, for example with Task Manager or `Stop-Process -Force`, it cannot clean up: after the gateway exits, delete that seat's `cotal-hermes-*` folder under `%TEMP%`, identified by `HERMES_HOME` in the launch output.
Windows does not support detached Hermes launches, adopted profiles, or `--resume`.

## Choose a model [#choose-a-model]

Use `--model <model>` or the persona file's `model:` field.
The flag takes precedence.
`cotal models --harness hermes` lists the models of the provider Hermes selects from the environment a launch receives, including the names in `spawn.env`.
See [Model catalog](hermes-connector-reference.mdx#model-catalog).
`--variant <effort>` or the persona file's `variant:` sets Hermes's reasoning effort, one of the variants `cotal models` lists.

A managed profile does not read your `~/.hermes` configuration.
The launch fails if neither source provides a model, even if you forward `HERMES_MODEL` through `spawn.env`.
Direct `cotal spawn` checks for the model before issuing credentials, and its `--dry-run` checks it without running `uv`.
On macOS and Linux, if both `uv` and the model are missing, foreground `cotal spawn` reports both in the same refusal.
On Windows, install `uv.exe` before retrying. The launch checks the model after it finds `uv.exe`.
To use your existing model configuration, [adopt your own profile](#use-your-own-hermes-profile).

## Use a custom endpoint [#use-a-custom-endpoint]

On Hermes 0.19, for a custom OpenAI-compatible server that needs no API key, select the `custom` provider and forward its endpoint variables.
Add these names to `spawn.env` in your [Cotal configuration](config.mdx#launcher-variables):

```json
{ "spawn": { "env": ["HERMES_INFERENCE_PROVIDER", "CUSTOM_BASE_URL"] } }
```

Then set the variables on the host that builds the launch:

```bash
export HERMES_INFERENCE_PROVIDER=custom
export CUSTOM_BASE_URL=http://127.0.0.1:8000/v1
cotal spawn --harness hermes --model <model>
```

For a managed launch, the manager must receive those variables.
Exporting them only in a later caller shell does not change an already running manager's environment.
The connector forwards its declared provider keys and the names in `spawn.env`; it does not inherit your whole shell.
`cotal models --harness hermes` then lists the models the endpoint serves.

On Windows, to use a keyed custom endpoint with a managed profile, also include `CUSTOM_API_KEY` in `spawn.env`.
Set it in the launch environment, not in the Cotal configuration. With `HERMES_INFERENCE_PROVIDER=custom`, the connector writes the model, URL, and key into the seat's private profile and removes the profile on a clean stop.

On macOS and Linux, for an endpoint that requires a key, [adopt your own profile](#use-your-own-hermes-profile) and set its `config.yaml` model block:

```yaml
model:
  default: <model>
  provider: custom
  base_url: https://llm.example.com/v1
  api_key: <key>
```

Cotal passes the model name unchanged.
`--model custom:<model>` does not select a provider.

## Gateway ownership [#how-it-binds]

Each seat runs a gateway with a Python plugin and a Cotal launcher that owns the mesh connection.
The seat joins only after the gateway's plugin authenticates its bridge subscription.
An immediate gateway exit fails the launch instead of reporting that the agent joined.
The default profile is private to the seat and removed on stop, except when it holds a resumed fork.
See the [Hermes connector reference](hermes-connector-reference.mdx#gateway-ownership) for process ownership, cleanup, and delivery behavior.

## Use your own Hermes profile [#use-your-own-hermes-profile]

Use this mode when Hermes needs your existing credentials or gateway integrations.
The connector replaces `plugins/cotal` on each launch and writes `cotal-tools.json`.
It leaves `SOUL.md` and `config.yaml` unchanged.

<Callout type="warn" title="The gateway uses your real profile">

Hermes still writes its own sessions, logs, lock files, and settings.
Its first-use hints can rewrite `config.yaml`, remove comments, and change formatting.
Your approval settings remain in effect, but this gateway has no interactive approval prompt for a human to answer.
A launch with `askPermissions` is refused here, because it cannot change your approval settings.
A persona that would overwrite your `SOUL.md` is refused.

</Callout>

Before the launch, enable the plugin and platform in that profile's `config.yaml`:

```yaml
plugins:
  enabled: [cotal]
gateway:
  platforms:
    cotal:
      enabled: true
```

To keep Hermes from rewriting this file for first-use hints, also mark the hints as seen:

```yaml
onboarding:
  seen:
    profile_build_offered: true
    busy_input_prompt: true
    tool_progress_prompt: true
```

The default agent file created by `cotal setup` has a Markdown body, which Cotal cannot apply to an adopted profile.
In your Cotal project, create a separate file at `.cotal/agents/hermes-adopt.md` with only this YAML frontmatter and no text after the closing `---`:

```markdown
---
name: hermes-adopt
---
```

Select that file and set the absolute profile path in the environment of the process that builds the launch:

```bash
export COTAL_HERMES_ADOPT_HOME="$HOME/.hermes"
cotal spawn --foreground --harness hermes --file .cotal/agents/hermes-adopt.md
```

This example uses direct execution so the launcher reads this shell's setting.
For managed execution, set the variable in the manager's environment instead.
The path must already exist and be a directory.
Relative paths and an unexpanded `~` are refused.
Missing plugin or platform settings also refuse the launch.

## Fork an existing session [#resume-a-session]

`--resume` copies a session from `HERMES_HOME`, or `~/.hermes`, into the seat's managed profile.
It does not append to the source transcript.
SQLite can still create `state.db-wal` and `state.db-shm` beside the source database.

```bash
cotal spawn --harness hermes --model <model> --resume <session-id>
```

Use the same seat name to continue its saved fork on a later launch.
The source must exist and contain messages on the first launch.
A different source under a name that already holds a fork is refused.
Inspect the source ID, title, and transcript hash with `cotal ps --wide`.

Stopping a resumed seat keeps its managed root at `$TMPDIR/cotal-hermes-<id>`.
Remove that root only when the seat has stopped and you no longer need its fork.
Resume cannot be combined with `COTAL_HERMES_ADOPT_HOME`; use Hermes' `/resume` within your own profile instead.
See [Session forks](hermes-connector-reference.mdx#session-forks) for per-chat branches and saved state.

## Presence [#how-presence-follows-the-turn]

Hermes reports `working` for model and tool calls, `waiting` for approvals, and `idle` at turn completion,
including a turn that ends because the provider failed.
Gateway reconnects and session starts do not finish a run turn.
See the [presence mapping](hermes-connector-reference.mdx#presence-mapping) for hook details.

## Event plane [#event-plane]

Each seat publishes its turns as AG-UI events on its event channel, so an [ACP client](acp-clients.mdx) or a dashboard can show them.
The events carry runs, the model's text, and tool calls with their status.
The text streams while the model writes it, when the provider streams its responses.
The model's reasoning is added only for a launch with `reasoningEvents`, which an [ACP client](acp-clients.mdx) thread sets.
Tool arguments and results ride the payload rail.
Add `--no-events`, or `events: false` in a manifest or workflow, to launch without it.
See [Event plane](hermes-connector-reference.mdx#event-plane) for how turns become runs.

## Approve commands [#approve-commands]

A launch with `askPermissions` keeps Hermes's command approvals on.
Each command Hermes stops for approval appears on the agent endpoint, and an [ACP client](acp-clients.mdx) thread shows it as a permission request.
See [Command approvals](hermes-connector-reference.mdx#command-approvals) for the choices, the timeout and what Hermes does not ask about.

## Answer questions [#answer-questions]

A question the model asks with Hermes's clarify tool in the owner's chat appears on the agent endpoint, and an ACP thread shows it as a form.
See [Clarify questions](hermes-connector-reference.mdx#clarify-questions).

## Turns from the owner [#owner-turns]

On a per-user mesh, the seat's owner can give it turns in their own words, images included, run the gateway's slash commands and skill commands, stop its work in progress, and read how full its context window is, through its [agent endpoint](connector-runtime-reference.mdx#agent-commands).
Each turn and command runs in the gateway's operator chat, apart from the sessions that peer messages start.
See [Agent commands](hermes-connector-reference.mdx#agent-commands) for which commands it lists, when a turn starts and what a stop does.

## Route answers to the right session [#how-an-answer-finds-its-session]

Each seat uses one Hermes session per channel, shared by everyone who messages the seat there.
Direct messages use a separate session for each peer.
Answers to `cotal_dm` and `cotal_anycast` return to the session that asked when their correlation and sender checks pass.
For a question asked on another Hermes platform, such as Telegram, enable gateway injection in the Hermes profile:

```yaml
plugins:
  entries:
    cotal:
      allow_gateway_injection: true
```

Cross-platform answers require Hermes 0.20.1 or later within the supported range.
Earlier versions route the answer into the peer's DM session.
Without injection permission, the answer stays buffered and is retried every 30 seconds.
Other messages continue to arrive.
See [Answer routing](hermes-connector-reference.mdx#answer-routing) for correlation limits and reply behavior.

## Unsupported launches [#limits]

Hermes refuses arbitrary `--opt` values and exact-session continuation.
An adopted profile also refuses a model variant.
It cannot run in the current deployment image.
You supply `uv` and the supported Python environment.
