## Terminal console [#terminal-console]

Run `cotal console` for an interactive terminal display.
A pipe or `--plain` selects the timestamped line stream for scripts and CI logs.
The console ships with the CLI and can perform separately authorized operator actions.
See [Use the console](console.mdx#terminal-console) for keys, controls, attachment, and reply behavior.

## Web dashboard [#web-dashboard]

Configure the `@cotal-ai/web` service before starting it with `cotal service start web`.
The dashboard ships with `cotal-ai` and is seeded automatically, but it is separate from stack startup.
It requires a registered static-auth root, a protected credential file, and explicit read-only intent.
See [Use the web dashboard](web-dashboard.mdx#web-dashboard) for setup and private browser access.

## Check visibility limits [#what-each-surface-can-see]

The credential and display determine what you can see:

| Display | Visibility |
| --- | --- |
| Console TUI | Selects only chat when credentials or a user bearer are present, even with admin grants. Without either, uses a whole-space tap on an open mesh. |
| Console line stream | Uses the same chat or whole-space tap selection as the TUI. |
| Dashboard service | Uses the protected file you supply and its grants. It does not mint a replacement admin credential. |

A chat-only credential hides DM views. A restricted read does not prove that a peer or DM is absent.
Neither display starts the mesh's dependencies automatically.
See [Identity](identity-and-auth.md) for observer and admin scopes and the [wire specification](../SPEC.md) for visibility guarantees.
