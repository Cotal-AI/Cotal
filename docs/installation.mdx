Install the `cotal` command on your machine, then use the Quickstart to create your first space.
Choose the shell installer on macOS or Linux, or use npm if you already have Node.js.

## Use the shell installer

The installer supports x64 and arm64 machines.
On Linux, use a glibc distribution such as Debian, Ubuntu, Fedora, or Arch.
Alpine and other musl distributions are not supported.

If the installer needs to download Node.js, it requires `curl` or `wget`, `tar` with gzip support,
`mktemp`, and a SHA-256 tool (`sha256sum`, `shasum`, or `openssl`).
Minimal cloud images may omit `tar`. On Rocky Linux 9, install it before running the installer:

```bash
sudo dnf install tar
```

This prerequisite step uses your system package manager.
The Cotal installer does not run sudo or install system packages.

Read the [installer script](https://get.cotal.ai) before you run it.
To install without opening guided setup:

```bash
curl -fsSL https://get.cotal.ai | sh -s -- --no-setup
```

Run the installer as your own user, without sudo.
Rerunning it installs the selected release and runs `cotal update` to reconcile the existing installation.
`--version <target-version>` keeps that release installed instead of selecting latest again.
You can rerun it with Cotal's `nodebin` directory on PATH without replacing its runtime links with links to themselves.
It installs inside your home directory and checks downloaded Node.js files against their published SHA-256 sums.
It uses a suitable Node.js 22.10 or newer already on your machine, or installs one for Cotal.

Before reporting success, the installer runs the installed launcher with `--version`.
If it cannot start, installation exits with an error and prints the command's output.
If you selected an older release, run the installer again without `--version` to select the latest release.
If the latest release cannot start, report the error at the [issue tracker](https://github.com/Cotal-AI/Cotal/issues).

The launcher goes in `~/.local/bin/cotal`.
The install root defaults to `${XDG_DATA_HOME:-~/.local/share}/cotal`.
The installer updates your shell configuration to add the launcher directory to PATH.
Its files are not writable by other users.

To install and open guided setup in one command instead, omit `--no-setup`:

```bash
curl -fsSL https://get.cotal.ai | sh
```

For the manual Quickstart, choose not to start a session at the end of setup.
The Quickstart starts the prepared space separately.

## Install with npm

If you already have Node.js 22.10 or newer, install as your own user, without sudo.
With an older Node, an unqualified `npm install -g cotal-ai` can silently select an old release
whose Node requirement matches. Use the explicit latest tag and engine check below so npm
refuses an unsupported Node instead. Upgrade Node first, or use the shell installer above.
An old installation's `cotal update --self` may replace it with a release that cannot run on
your Node. Upgrade Node before updating that installation.
The npm global prefix must be writable by your user, and its executable directory must be on PATH.
On macOS or Linux with distribution Node, the default prefix may be root-owned.
Use the [shell installer](#use-the-shell-installer) above, or select a user-owned npm prefix before installing:

```bash
npm config set prefix "$HOME/.local"
export PATH="$HOME/.local/bin:$PATH"
npm install -g cotal-ai@latest --engine-strict
```

The prefix setting applies to all future npm global installs, not just Cotal.
Add the same `export PATH="$HOME/.local/bin:$PATH"` line to your shell startup file
(such as `~/.bashrc` or `~/.zshrc`) so new terminals can find `cotal`.
If an install fails with npm `EACCES`, use one of these routes instead of retrying with sudo.

On Windows, or when your existing npm prefix is already user-writable and its executable directory is on PATH, run:

```bash
npm install -g cotal-ai@latest --engine-strict
```

Use this route on Windows.
The shell installer does not support Windows shells.
You can also use the shell installer inside WSL.

Cotal includes a `nats-server` binary for its local broker.
If you put your own `nats-server` on PATH, Cotal uses it when its folder is not writable by other accounts.
Otherwise it uses the bundled binary. `cotal up` refuses a selected broker older than 2.12 and names its path and version.
`cotal status` shows which binary Cotal will run.
An older deployment with a file-backed presence bucket needs 2.14.5 or newer to avoid a known write failure.
See [Run a mesh](run-a-mesh.mdx#the-stack) before reusing an existing broker.

The CLI sends usage telemetry by default. Run `cotal telemetry off` to disable it.
[Telemetry](telemetry.mdx) lists the fields and other opt-outs.

## Check the installation

Reinstalling over retained daemon records reconciles the owned service before reporting success.
On Linux, if its old Node runtime was removed with the shell installation, the installer binds the unchanged service to the Node it selected for the same CLI entry.
It does not adopt a service from another installation or overwrite an edited unit.

Open a new terminal, then run:

```bash
cotal version
```

This reports the Cotal binary version and the installed extension versions.
If the command is missing, check that the installer's launcher directory is on PATH.

If an older installation runs, use the absolute launcher path printed by the installer.
On macOS and Linux, `type -a cotal` lists shell aliases, functions, and executable candidates.
Correct PATH order and refresh your shell's command cache, or open a new terminal.
Do not use older force-seed instructions to repair command selection.

## Choose installer options

Pass shell-installer options after `sh -s --`:

```bash
curl -fsSL https://get.cotal.ai | sh -s -- --dry-run
```

The options used most often are:

| Option | Effect |
|---|---|
| `--dry-run` | Reports the planned changes without making them. |
| `--no-setup` | Installs Cotal without opening guided setup. |
| `--no-modify-path` | Prints the PATH change instead of editing shell configuration. |

Use `--help` for the full list.

## Remove Cotal

Stop the spaces and agents that use this installation before removing its files.
For an npm installation, run:

```bash
npm uninstall -g cotal-ai
```

For a shell installation with the default locations, remove `~/.local/bin/cotal` and the `cotal` directory under `${XDG_DATA_HOME:-~/.local/share}`.
If you selected custom install locations, remove those locations instead.
Delete the `# cotal` block the installer added to your shell configuration.

Deleting `~/.cotal` also deletes machine-local mesh records, agent data, and credentials.
Keep or back up that data unless you intend to remove it.
Project folders can hold their own `.cotal` directories.
Removing the installation does not remove those project files.
