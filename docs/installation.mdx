Install the `cotal` command on your machine, then use the Quickstart to create your first space.
Choose the shell installer on macOS or Linux, or use npm if you already have Node.js.
For the `.deb` and `.rpm` desktop packages, see [Install the desktop app on Linux](#install-the-desktop-app-on-linux).

## Use the shell installer

The installer supports x64 and arm64 machines.
On Linux, use a glibc distribution such as Debian, Ubuntu, Fedora, RHEL, AlmaLinux, Rocky Linux, or Arch.
Alpine and other musl distributions are not supported.

If the installer needs to download Node.js, it requires `curl` or `wget`, `tar` with gzip support,
`mktemp`, and a SHA-256 tool (`sha256sum`, `shasum`, or `openssl`).
Minimal cloud images may omit `tar`. On RHEL, AlmaLinux, or Rocky Linux 9, install it before running the installer:

```bash
sudo dnf install tar
```

This prerequisite step uses your system package manager.
The Cotal installer does not run sudo or install system packages.

Read the [installer script](https://get.cotal.ai) before you run it.
The following command requires `curl`. It installs Cotal without opening guided setup:

```bash
curl -fsSL https://get.cotal.ai | sh -s -- --no-setup
```

If you have `wget` instead of `curl`, run:

```bash
wget -qO- https://get.cotal.ai | sh -s -- --no-setup
```

Run the installer as your own user, without sudo.
Rerunning it installs the selected release and runs `cotal update` to reconcile the existing installation.
Use `--version <target-version>` or `--version=<target-version>` to select a specific release.
Omit `--version` to install the latest release. An empty or whitespace-only version stops the installer before it writes any files.
The installer stages and starts the requested release before replacing the active package,
runtime links or launcher. If that startup check fails, the previous installation still works.
Before a downgrade, the installer checks the connector seed store the requested release would use.
That release uses its own retained connector set when one exists. If the applicable store is newer
than the requested release, the installer keeps the installed release. Use it, or restore compatible
connector state from a backup before retrying the downgrade.
If an older release starts but reconciliation fails, the installer restores the previous release.
You can rerun it with Cotal's `nodebin` directory on PATH without replacing its runtime links with links to themselves.
It installs inside your home directory and checks downloaded Node.js files against their published SHA-256 sums.
It uses a suitable Node.js 22.10 or newer already on your machine, or installs one for Cotal.
When the installer uses your system `node`, the launcher keeps using that executable path after
a supported Node upgrade. If that path disappears or Node falls below 22.10, rerun the installer.

Before reporting success, the installer runs the installed launcher with `--version`.
If it cannot start, installation exits with an error and prints the command's output.
If you selected an older release, run the installer again without `--version` to select the latest release.
If the latest release cannot start, report the error at the [issue tracker](https://github.com/Cotal-AI/Cotal/issues).

The launcher goes in `~/.local/bin/cotal`.
If a file occupies the launcher directory or a directory occupies the launcher path, both `--dry-run` and a normal install stop before making changes.
Move the obstruction aside or set `COTAL_BIN_DIR` to a different launcher directory.
The install root defaults to `${XDG_DATA_HOME:-~/.local/share}/cotal`.
If the launcher directory is not already on PATH, the installer updates your shell configuration.
On Linux with Bash, it updates `~/.bashrc` and the first readable login file: `~/.bash_profile`, `~/.bash_login`, or `~/.profile`.
If none exists, it creates `~/.profile`.
The installer preserves existing lines and leaves matching PATH blocks in place.
It does not run startup files to check their effect. If it finds matching lines or cannot update
a startup file, it prints the export command to use if your shell cannot find `cotal`.
The installer's files are not writable by other users.

To install and open guided setup in one command instead, omit `--no-setup`:

```bash
curl -fsSL https://get.cotal.ai | sh
```

For the manual Quickstart, choose not to start a session at the end of setup.
The Quickstart starts the prepared space separately.

## Install with npm

On Linux, use a glibc distribution to start the built-in PTY manager. The default local stack
uses that manager. Alpine and other musl distributions cannot start it.

If you already have Node.js 22.10 or newer, install as your own user, without sudo.
On older Node.js versions, the npm postinstall check stops the installation and reports the running and required versions.
Install a supported Node.js and retry, or use the [shell installer](#use-the-shell-installer) on macOS or Linux.
The npm global prefix must be writable by your user, and its executable directory must be on PATH.
On macOS or Linux with distribution Node, the default prefix may be root-owned.
Use the [shell installer](#use-the-shell-installer) above, or select a user-owned npm prefix before installing:

```bash
npm config set prefix "$HOME/.npm-global"
export PATH="$HOME/.npm-global/bin:$PATH"
npm install -g cotal-ai
```

The prefix setting applies to all future npm global installs, not just Cotal.
Add the same `export PATH="$HOME/.npm-global/bin:$PATH"` line to your shell startup file
(such as `~/.bashrc` or `~/.zshrc`) so new terminals can find `cotal`.
If an install fails with npm `EACCES`, use one of these routes instead of retrying with sudo.

On macOS or Linux, if your existing npm prefix is already user-writable and its executable directory is on PATH, run:

```bash
npm install -g cotal-ai
```

On Linux and macOS, a global npm install with lifecycle scripts enabled records the Node executable used to install Cotal.
The `bin/cotal` link in the npm prefix points to a shell launcher. It prefers a supported Node on PATH.
If PATH has no Node or its Node is too old, the launcher uses the recorded executable when available and supported.
The launcher finds the JavaScript entry in the installed package, even when a package manager moves the installation after running the scripts.
The package's JavaScript entry stays the same for daemon services and per-home connector state.
If neither executable can run Cotal, restore a supported Node to PATH and reinstall Cotal with npm.

Cotal includes a `nats-server` binary for its local broker.
If you put your own `nats-server` on PATH, Cotal uses it when its folder is not writable by other accounts.
Otherwise it uses the bundled binary. `cotal up` refuses a selected broker older than 2.12 and names its path and version.
`cotal status --verbose` shows which binary Cotal will run in the `NATS` row of the `Machine` section.
An older deployment with a file-backed presence bucket needs 2.14.5 or newer to avoid a known write failure.
See [Run a mesh](run-a-mesh.mdx#the-stack) before reusing an existing broker.

The CLI sends usage telemetry by default. Run `cotal telemetry off` to disable it (`cotal.cmd telemetry off` on Windows).
[Telemetry](telemetry.mdx) lists the fields and other opt-outs.

### Install on Windows

Use npm in PowerShell, Command Prompt, or Git Bash. The shell installer works inside WSL, not in a native Windows shell.
PowerShell can pick `npm.ps1` and `cotal.ps1` for the bare commands. If your execution policy blocks
these scripts, use `npm.cmd` and `cotal.cmd` without changing the policy.
When the npm launcher is on PATH, `cotal.cmd status` and the entry card suggest commands that use `cotal.cmd`.

Use a short, writable npm global prefix and put that directory on PATH. Run `npm.cmd prefix -g` to see the current prefix.
If the current prefix is suitable, run:

```powershell
npm.cmd install -g cotal-ai
```

A long prefix can stop npm from starting the install script even when Windows long paths are enabled.
If npm does install successfully, PowerShell, Command Prompt, or Git Bash can still fail to run the generated `cotal` launcher.

To install into a shorter prefix without changing npm's default, open a terminal in a short, writable folder and run:

```text
npm.cmd install -g --prefix . cotal-ai
```

Add that folder to your user PATH before the old prefix, then [check the installation](#check-the-installation).
Use the same prefix for later manual npm installs and removals of this copy.

### Switch from a shell installation

To upgrade the shell-installed copy, run `cotal update --self` using its launcher.
To use npm's CLI instead, install it in a separate prefix as shown above, with its `bin` directory
first on PATH. The default shell launcher already occupies `~/.local/bin/cotal`.
Do not use `npm --force` to overwrite it.
Keep the shell installation and its files if your user daemon still uses them. Changing PATH
picks the npm CLI for new shell commands without moving the daemon or deleting any spaces.
Use the original launcher's absolute path to manage its installation and daemon.

## Install the desktop app on Linux

GitHub releases publish x64 Linux desktop packages as `.deb` (`Cotal_<version>_amd64.deb`) and `.rpm` (`Cotal-<version>-1.x86_64.rpm`).
Both packages require WebKitGTK 4.1 (`libwebkit2gtk-4.1.so.0`) and the Ayatana AppIndicator tray library (`libayatana-appindicator3.so.1`).

Tested on (`<dir>` is the folder holding the downloaded package):

- **Ubuntu 24.04 (`.deb`):**

  ```bash
  sudo apt-get install <dir>/Cotal_<version>_amd64.deb
  ```

- **Fedora 45 (`.rpm`):**

  ```bash
  sudo dnf install <dir>/Cotal-<version>-1.x86_64.rpm
  ```

- **openSUSE Tumbleweed (`.rpm`):** The published `.rpm` is unsigned, so pass `--allow-unsigned-rpm`:

  ```bash
  sudo zypper install --allow-unsigned-rpm <dir>/Cotal-<version>-1.x86_64.rpm
  ```

- **CentOS Stream 10 (`.rpm`):** Enable EPEL and CRB as root before installing the `.rpm`:

  ```bash
  dnf install dnf-plugins-core epel-release && dnf config-manager --set-enabled crb
  ```

  Then install the `.rpm`:

  ```bash
  sudo dnf install <dir>/Cotal-<version>-1.x86_64.rpm
  ```

Enterprise Linux 10 needs EPEL and CRB (CodeReady Builder on RHEL) for WebKitGTK 4.1 and the tray library. Without both enabled, `dnf` refuses the `.rpm` with `nothing provides libayatana-appindicator3.so.1()(64bit)` and `nothing provides libwebkit2gtk-4.1.so.0()(64bit)`.

### Enterprise Linux 9

RHEL 9, AlmaLinux 9, and Rocky Linux 9 ship WebKitGTK 4.0 (`webkit2gtk3`), and EPEL 9 does not add WebKitGTK 4.1.
The desktop `.rpm` cannot be installed on version 9 (`dnf` fails with `nothing provides libwebkit2gtk-4.1.so.0()(64bit)` even with EPEL and CRB enabled).

On RHEL, AlmaLinux, or Rocky Linux 9, use the [command-line install](#use-the-shell-installer) instead.
The shell installer installs `cotal-ai` with its own Node 24 runtime, and the background service runs without the desktop window (tested on AlmaLinux 9.9):

```bash
sudo dnf install tar
curl -fsSL https://get.cotal.ai | sh -s -- --no-setup
cotal daemon install
cotal daemon status
```

Open a new shell first if `~/.local/bin` was just added to `PATH`. `cotal daemon status` reports `ready` once the service is running.

## Check the installation

Reinstalling over retained daemon records reconciles the owned service before reporting success.
On Linux, if its old Node runtime was removed with the shell installation, the installer binds the unchanged service to the Node it selected for the same CLI entry.
It does not adopt a service from another installation or overwrite an edited unit.
If the destination launcher belongs to a different npm installation and a daemon service is recorded, both `--dry-run` and a normal shell install stop before making changes.
Keep the npm installation and run `cotal update --self`, or stop your spaces and run `cotal daemon uninstall` from the installation that owns the service before switching.

On macOS or Linux, or in Git Bash on Windows, open a new terminal and run:

```bash
cotal version
```

On Windows, open a new PowerShell or Command Prompt window and run:

```powershell
cotal.cmd version
```

This reports the Cotal binary version and the installed extension versions.
If the command is missing, check that the launcher's directory is on PATH. For a Windows npm install,
this is the npm global prefix itself, not a `bin` subdirectory.

If an older installation runs, use the absolute launcher path printed by the installer.
On macOS and Linux, `type -a cotal` lists shell aliases, functions, and executable candidates.
Correct PATH order and refresh your shell's command cache, or open a new terminal.
Do not use older force-seed instructions to repair command selection.

## Choose installer options

Pass shell-installer options after `sh -s --`:

```bash
curl -fsSL https://get.cotal.ai | sh -s -- --dry-run
```

The options used most often are:

| Option | Effect |
|---|---|
| `--dry-run` | Reports the planned changes without making them. |
| `--no-setup` | Installs Cotal without opening guided setup. |
| `--no-modify-path` | Prints the PATH change instead of editing shell configuration. |

Use `--help` for the full list.

## Remove Cotal

For any installation method, stop the local spaces and agents that use this installation first.
In PowerShell or Command Prompt, use `cotal.cmd` in place of `cotal` in the following daemon commands.
Run `cotal daemon status` to check the machine daemon. A daemon that is not running can still have an installed service.
If you installed the machine daemon, run `cotal daemon uninstall` from the installation that owns it before removing any CLI files.
In a script, use `cotal daemon uninstall --yes`. If you installed with `--daemon-home`, pass the same option and directory to both daemon commands.
If the daemon uninstall fails, resolve the error before continuing.

For an npm installation on macOS or Linux, remove the package and any generation store created by `cotal update --self`:

```bash
rm -rf "$(npm root -g)/../.cotal-generations"
npm uninstall -g cotal-ai
```

On Windows, remove a default-prefix installation with:

```powershell
npm.cmd uninstall -g cotal-ai
```

If you installed with `--prefix .`, open a terminal in that same folder and run:

```text
npm.cmd uninstall -g --prefix . cotal-ai
```

For a shell installation with the default locations, remove `~/.local/bin/cotal` and the `cotal` directory under `${XDG_DATA_HOME:-~/.local/share}`.
If you selected custom install locations, remove those locations instead.
Delete each `# cotal` block the installer added to your shell startup files.

Removal leaves your project files, the [operator configuration directory](config.mdx#configuration-files), and systemd linger in place.
The configuration directory holds settings, installed extensions, and the built-in connector seed store.
The directory is `$XDG_CONFIG_HOME/cotal` when `XDG_CONFIG_HOME` is non-empty. Otherwise it is `%APPDATA%\Cotal` on Windows when `APPDATA` is set, or `~/.config/cotal`.
For complete removal, back up any settings you want to keep, then delete that directory only if no other Cotal installation or running Cotal process uses it.

Deleting `~/.cotal` also deletes machine-local mesh records, agent data, and credentials.
Keep or back up that data unless you intend to remove it.

If the CLI is already gone on Linux, run `systemctl --user disable --now cotal-daemon.service`, remove `~/.config/systemd/user/cotal-daemon.service`, then run `systemctl --user daemon-reload`.
If you used a custom daemon home or the user manager uses a custom config directory, use the installed unit's actual name and file path instead.
This removes the systemd service only. See [Daemon commands](cli-processes.mdx#daemon) for how the CLI removes native services and their daemon records.
