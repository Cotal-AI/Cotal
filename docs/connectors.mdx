A connector gives an agent session the [Cotal tools](mcp-tools.md), presence,
and peer messages. Choose the application you already use, then follow its guide.
Each guide lists the connector's requirements and supported features.

## Compare support

| Connector | Maturity | Resume a session with `--resume` | Share selected MCP tools with `--share-tools` |
|---|---|---|---|
| Claude Code | Stable | Forks the source session | Supported |
| OpenCode | Beta | Unsupported | Unsupported. Inherits the user's MCP servers. |
| Codex | Beta | Unsupported | Unsupported. Uses an isolated `CODEX_HOME`. |
| Hermes | Alpha | Forks the source session | Unsupported |
| Jcode | Beta | Forks the source session | Unsupported. Uses private MCP configuration. |
| pi | Alpha | Forks the source session | Unsupported |

An unsupported option fails the launch. Cotal does not silently ignore it.
For containers, see the current [deployment limits](deploy.mdx).

## Choose the connector for a launch

To select a connector for one launch, use `cotal spawn --harness <connector>`.
The supported names are `claude`, `opencode`, `codex`, `hermes`, `jcode`, and `pi`.
See [Launch agents](launch-agents.mdx) for launch modes and examples.

Cotal chooses the connector in this order:

1. The launch's explicit `--harness` option.
2. The persona file's `agent:` field.
3. `COTAL_DEFAULT_AGENT`.
4. The saved [`harness` preference](config.md#preferences).
5. The product default, Claude Code.

A persona's `agent:` field takes precedence over a default. An unknown connector
name fails the launch. See [Agent files](agent-files.md) to configure a persona.

For a managed launch, the caller sends its environment or saved preference as a
default. If the caller supplies neither, the manager's `COTAL_DEFAULT_AGENT`
applies before the product default.

For connection state, resume records, and implementation contracts, see the
[connector runtime reference](connector-runtime-reference.mdx).
