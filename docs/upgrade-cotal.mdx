Upgrade an existing installation without recreating its space identity or losing its trust material.
Use the [upgrade history](UPGRADING.md) for the migration instructions that apply to your source and target releases.
A computer that has never had `~/.config/cotal` needs one manual `npm install -g cotal-ai@latest` to receive the missing-config updater fix.

## Execution generations

The `cotal` entry reads a versioned execution descriptor when one is present.
A descriptor bound to this package's name, version and bootstrap hash selects a retained
package only after its inventory verifies. A descriptor may also list up to four validated
artifact bindings for a bootstrap and manifest transition. A missing or differently bound descriptor runs
the installed tree in place and writes nothing. An invalid matching descriptor refuses
with reinstall guidance rather than selecting another generation.
A running command reports the release of its loaded implementation, even if the canonical
package manifest changes while it runs.

This entry and generation-store support does not change `cotal update --self` yet.
The updater still uses its existing installation and recovery path.

## Plan the upgrade

From the project's folder, record the current installation and mesh state:

```bash
cotal version
cotal status
```

Choose an exact target version, such as `0.N.P`, rather than a version range.
Read every applicable migration section between the installed version and the target release before changing the deployment.
Treat notes marked unreleased as unreleased until the target release includes them.

List the hosts that run the broker, auth service, managers, CLI, and connectors.
Use each release section's component order for a split deployment.
Plan a downtime window. The current upgrade contract does not promise rolling upgrades or mixed authority versions.

If a service manager or container owns the native stack's lifetime, check its launch command before upgrading.
Background startup is the default for `cotal up`; a supervisor that must own the stack needs `cotal up --foreground`.
See [Supervise the stack](supervise-processes.mdx).

## Prepare for downtime

Save agent work and arrange a quiet maintenance window before stopping services.
Pause automatic restarts and new managed launches when the applicable migration requires them.

<Callout type="warn" title="Check shutdown and backup limits first">

Built-in `pty` seats stop with their manager, including a normal `cotal down`.
An older manager may also have different shutdown guarantees.
Read [Stop the stack](run-a-mesh.mdx#stop-the-stack) before choosing the stop command.

A controller-owned stack cannot use the preserve, backup, or restore commands in this release.
Use the deployment's supported protected backup procedure for its durable state and trust material.
The [offline backup guide](backup-a-mesh.mdx) describes the supported mesh types and their limits.

</Callout>

Take the snapshots required by the applicable release section before any migration writes occur.
A Cotal backup artifact contains no credentials or trust secrets, so protect the original trust material separately.
Stop components in the release section's stated order.
For an ordinary local whole-stack shutdown, use the procedure in [Run a mesh](run-a-mesh.mdx#stop-the-stack).

## Install the target version

Use the same installation route and prefix that currently supply your `cotal` command.
Replace `<target-version>` with the exact version you selected.

### Shell installation

Read the [installer script](https://get.cotal.ai) before running it, then pin the target release:

```bash
curl -fsSL https://get.cotal.ai | sh -s -- --version <target-version> --no-setup
```

If the original installation used custom locations, supply those same locations again.
See [Install Cotal](installation.mdx) for installer options and PATH checks.

### npm installation

For an npm installation, run:

```bash
npm install -g cotal-ai@<target-version>
```

Open a new terminal or use the installer's absolute launcher path if the shell still selects the previous installation.
Run `cotal version` and confirm that the selected binary is the target version before continuing.

## Reconcile the installation

On versions 0.159.1 through 0.160.7, a home that was never configured can refuse `cotal update --self` with `update snapshot refused: ENOENT` because its configuration directory does not exist. Rerun the installer:

```bash
curl -fsSL https://get.cotal.ai | sh -s -- --no-setup --no-modify-path
```

Then run `cotal version` and `cotal status` using the installer's launcher at `~/.local/bin/cotal`.

From the prepared project folder, run the target version's command:

```bash
cotal update
```

This reconciles installed extensions and connector integrations with the running CLI's release.
It checks running-manager continuity before installation repair.
On Linux, a supervisor in another user's installation or an isolated container does not add local
custody. A supervisor that resolves to this installation still counts, including one launched
through sudo. If attribution remains uncertain, update refuses with the process ID, numeric user
ID and stop command before contacting an unselected remote Manager.
On 0.164.6 and older, an unrelated container or another user's Manager can instead produce
`a manager for this mesh runs on this machine; reading its custody`, followed by
`running manager continuity check` and a refused manager-caller exchange. That old updater
refuses before replacing itself, so another `cotal update --self` cannot load this fix while the
foreign supervisor runs. Rerun the installer to replace the package and run the new release's
own reconciliation:

```bash
curl -fsSL https://get.cotal.ai | sh -s -- --no-setup --no-modify-path
```

Then run `cotal version` and `cotal status` with the installer's launcher at `~/.local/bin/cotal`.
Remote credential exchanges that time out or return HTTP 5xx retry for up to 120 seconds during
that check. Credential denials and other HTTP 4xx responses still fail without retry.
If it refuses, follow the reported remedy instead of removing credentials or reinstalling an unrelated copy.

`cotal update --check` only reports registry availability and recorded extension versions.
It installs and restarts nothing, so it does not replace this reconciliation step.
`cotal update --self` selects the validated latest release; use the pinned install commands above when you need a specific target.
Before replacing the global binary, it checks the release's first-party package archives through
npm. If the release is still reaching the registry, it refuses with retry guidance without starting
the global install or connector reconciliation.
If npm's install reports `ETARGET` for the selected latest `cotal-ai` version, the command
reports that the release is still arriving and exits 0 without replacing packages or rolling back.
This is a deferred update, not confirmation that the new version was installed. The next automatic
attempt retries after one hour without consuming the version's failure budget. You can also run
`cotal update --self` again later. Other npm resolution errors remain failures.

On macOS, the daemon bootstraps a separate one-shot launchd job in the signed-in user's GUI
domain before installation. The job runs the same guarded updater and is not kept alive after
exit. Restarting or booting out the daemon job does not stop the updater job. After the updater
exits, the daemon removes its recorded job and private plist only if their identities still match.
An unavailable launchd inspection keeps generation activation fenced and retries observation.
If the runner exits without a result, the daemon confirms the job has stopped, removes its owned
job, records one failed attempt, and retries within the normal failure budget after one hour.
It never starts another updater while the native job or runner is present.
A failed initial handoff reports its reason and `cotal update --self`; no detached child is substituted.
User logout and system shutdown can still interrupt the update.
A Mac on a version before this one needs one `cotal update --self`, and updates itself from then on.
CLI-only users must install the background service with `cotal daemon install` to receive automatic
installation. `cotal update --auto off` disables it.

On Linux, a daemon-started automatic update moves its authenticated updater parent and reconcile
child into a sibling systemd user scope before reconciliation. This requires cgroup v2,
`systemctl`, `busctl`, and a reachable user manager that permits transient scopes with existing
PIDs. The daemon remains in its service. Restart decisions stay with the existing updater.
The custody inspector accepts group-writable owned paths only for the caller's primary group
when bounded local account records show no other member or account using that group. Unknown
or external account sources are refused. This inspector does not examine extended ACLs.
This preserves updater availability during a service stop, but does not add startup verification
or rollback guarantees. If migration is refused, the package has already been replaced and
reconciliation has not started. The parent may retry or restore its previous package. Keep the
reported failure and inspect the installed version and daemon state before retrying.

## Recover an interrupted update

`cotal update --self` restores an interrupted update when its snapshot is a valid directory of
this installation. If the snapshot is absent, outside this configuration, or not a plain directory,
the command checks the recorded owner. A dead or reused owner lets it retain the unusable records
and continue installation and reconciliation. A live owner blocks the update and names its pid.
An unreadable owner process refuses with inspection guidance. A missing or malformed owner waits
one hour from the first observed contents. Retrying does not reset that wait.

Retired records stay in a timestamped `update-recovery-retained-<timestamp>-<suffix>` folder in the
Cotal home, normally `~/.cotal`. The command prints that folder. It never changes the snapshot
named by a retired record. The daemon uses the same rules, including unattended updates.

If a machine on 0.164.6 or older is stuck on an unusable interrupted-update record, rerun the installer:

```bash
curl -fsSL https://get.cotal.ai | sh
```

The old updater stops before it can replace itself. The installer supplies the repaired updater.

## Restart the mesh

Complete the release-specific credential and state migrations before restarting components.
Start them in the order specified for that release.

For a local background stack, return to its existing project folder and run:

```bash
cotal up --detach
cotal version
cotal status --components
```

Reuse the existing project root. Do not run `space create` or `space add` to replace an existing local mesh during an ordinary upgrade.
A foreground service must retain its `--foreground` launch mode.
Restart or reconnect agent applications when the migration instructions require them to load the new connector.

Confirm the target binary and installed extension versions, then check the component report for absent, not-serving, or refused components.
A version report describes the selected installation; it does not prove that every previously running process loaded the new code.
A Manager refuses new launches when an installed first-party connector's generation differs from
its loaded implementation, even if it previously imported that connector. Stop that Manager's
seats and restart it from the installed CLI. The refusal leaves existing seats running and does
not repair or roll back the shared connector store.
Resume new work only after the required components are serving and the release-specific checks pass.

If a migration or restart fails, keep the failed step's evidence and use [Recover a mesh](recover-a-mesh.mdx).
Installing an older package does not automatically undo credential or on-disk migrations.
Use the matching release's recovery instructions before restoring state or attempting a downgrade.
