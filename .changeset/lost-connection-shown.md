The desktop app now notices when this computer goes offline or a space stops answering. It used to keep showing Connected. A hosted Manager tells the machine daemon whether its connection to the space is up, on the health check that already runs every five seconds, and the daemon reports a loss once two checks in a row see it, so a drop the Manager recovers from within seconds shows nothing. The Manager now pings its connection every ten seconds, as agents already do, so a network that goes away without a word, as Wi-Fi does, is found within about 45 seconds rather than several minutes. When the connection drops, `cotal daemon status` and the app's live status show a `connection` problem. It reads `offline` when this computer cannot look up the space's host, and `unreachable` when it can but the space is not answering. The app says "No internet connection" or "Can't reach your space", and the tray says "Offline" or "Can't connect". The problem clears by itself once the Manager reconnects, and a Manager that a status read during the loss left `starting` is read again until it answers, at once and then at growing intervals of up to 30 seconds, so the app returns to Connected without anyone asking. `cotal daemon service-status` for a space with a hosted Manager succeeds only while that Manager answers with no lost connection; otherwise it refuses with the code `OFFLINE` or `SPACE_UNREACHABLE` for a lost connection, or `MANAGER_<STATE>` (such as `MANAGER_STARTING`) for the Manager's own state. The daemon logs each loss and reconnect once.
