The Hermes connector now supports `hermes-agent` 0.18 through 0.21 instead of pinning the 0.16 line, so the versions an operator can actually install are accepted. The launcher's check is a bounded range rather than an equality test on the major.minor string, and `pyproject.toml` declares the same range, because widening one of those alone leaves the other refusing what it resolves. Versions outside the range are still refused loudly, with an unreadable version treated as outside rather than waved through.

The gateway platform adapter accepts the keyword-only `is_reconnect` that `BasePlatformAdapter.connect` gained in 0.18 and that the gateway passes at every call site from then on, so a bumped pin no longer means a `TypeError` at platform connect after a clean plugin load. On a reconnect the bridge client is reopened, because `disconnect` latches its stop flag and leaves the reader thread finished, which would otherwise produce a platform that reports connected while receiving no mesh traffic.

Reopening retires the previous reader by generation rather than by checking whether it is still alive. A reader that has committed to exit but has not been scheduled yet still reads as alive, and treating it as the active handle left a platform marked connected whose bridge was deaf for the rest of the process. A timeout cannot tell "already gone" from "still unwinding", so the question is no longer asked: each reader carries the generation it was born into, and a reader from an older generation is retired whenever it actually finishes. Reopening also runs off the event loop, so a reader wedged in a blocking read cannot stall the other platforms in the same gateway while it is cleaned up.

A reader that is found dead is now reported as a retryable fatal instead of being marked connected, so the gateway's existing background reconnect queue picks the platform up. Nothing else would: the gateway revisits platforms that failed to connect or reported a fatal, and never re-probes one it believes is already connected.

Retirement now reaches the socket as well as the generation. A retired reader is usually blocked in a read on the socket it was using, where a generation check cannot reach it: that check only runs at the top of the reader loop, which the thread arrives at after its read returns. Leaving the socket in place therefore left two readers on one socket, and a message larger than a single read was split between them, with the retired reader taking a chunk and exiting while the installed reader was left holding a fragment that never completed a line. Small messages hid this entirely, because they arrive whole or not at all. Reopening now closes the socket as it retires the generation, so the read returns at once and the replacement dials its own.

Clearing the socket is now guarded by identity as well. The read loop's end-of-stream branch runs when the read returns nothing AND when it fails, which is exactly how a retired reader is woken, so clearing the shared socket there without checking it was the one being read let a retired reader erase the socket its replacement had already installed. The seat then went quiet in one direction only: every reply was dropped, because sending checks for a socket and gives up when there is none, while nothing on the sending side dials again. It stayed quiet until an inbound message happened to wake the reader.

Retiring a reader now shuts the socket down before closing it. Closing alone does not wake a thread that is already blocked reading: the close drops one reference to the connection while the blocked thread still holds its own, so the read never returns and that reader stays parked forever. Every reconnect left one more of them behind. Shutting down first acts on the connection rather than on the handle, so the parked read returns at once and the reader exits. This was invisible to every delivery check, because a reader stranded forever stops competing for the new socket just as effectively as one that exits.

A reader retired while it was still dialling is also re-checked after the dial returns, not only before it. Declining to install a socket is not the same as declining to read one: the dial returns having installed nothing, and the live generation's socket is sitting there to be read by a reader that no longer owns it.

`COTAL_HERMES_ADOPT_HOME` is a new opt-in that runs the gateway in your own Hermes profile instead of a disposable one, so a Hermes carrying your credentials and integrations can join the mesh. It installs only the connector's own plugin directory, reads your `config.yaml` without writing it, and leaves your `SOUL.md` alone. Enabling the plugin stays your decision, and a launch into a profile that has not enabled it fails with the settings to add.
