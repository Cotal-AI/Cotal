The remote gateway gets `cotal_wait`, so a hosted conversation can listen for messages. A remote MCP client cannot start a turn, so a hosted conversation heard a message only when it happened to call a tool. `cotal_wait` returns at once when a wake-worthy message is buffered and otherwise as soon as one arrives, with the reply `cotal_inbox` gives, or with none after a bound. Wake-worthy follows the agent's attention, as a local seat's push does. The bound is `GatewayOptions.waitSeconds` on `registerCotalGatewayTools`, or `waitSeconds` on `handleGatewayRequest`, and defaults to `GATEWAY_WAIT_SECONDS` (50 seconds), under Claude Code's 60-second limit to a remote server's first byte, Cloudflare's origin timeout and claude.ai's tool-call timeout. A wait whose client closes the request stops listening, and a read whose client is gone clears nothing, so neither takes a message it cannot deliver. A wait ends when its connection closes, and a focus @mention that lands between two waits ends the next one. `CotalToolSpec.run` takes an optional `ToolCall` with the request's `signal`, which `cotal_inbox` honors. Every other routed tool except `cotal_inbox` now adds a line to its result when messages are waiting, and the default instructions tell the model to listen with `cotal_wait`. `MeshAgent.inboxWake()` is the inbox half of `pendingWake()`, without run turns. `MeshAgent` emits `stopping` once when `stop()` begins, whatever the transport's state.
