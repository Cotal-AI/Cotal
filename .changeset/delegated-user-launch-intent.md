Specify a delegated user intent in a new SPEC §13.16 and a design record. A signed-in user admits one launch or one retirement on the host's authenticated route, and a platform control holder consumes that intent once from its current registration, epoch, assignment revision and lifecycle. The consuming write pins the lifecycle UID before any effect, so the host can finish or undo the execution after a crash or a lost answer, and a retirement can always find the delegated launch it ends. One flight runs each execution and a retried request joins it. Only the host process that consumed the intent can advance its launch; any other process, including that host after a restart, can only undo it at the pinned lifecycle UID. A launch activates its lifecycle before it writes any ledger row, so undoing it always reaches the terminal barrier, even before the agent's first bearer exchange. An undone launch keeps its agent name held until the process that ran it stops and releases it, or an operator does, so a late write from that process cannot replace a later agent's ledger row. The host enrolls the agent under the user's `u_` owner with the user's own actor as its ledger parent, through the same envelope walk, durables and membership as the user's own managed-agent enrollment, and retires it through the uid-exact prepare, provider closure and terminal barrier order, finishing alone when the holder is gone. The holder gains no grant, the `platform-control` view's same-owner rule is unchanged, and stock dispatch refuses both new kinds as `unimplemented`. The embedding guide says no stock door does this yet. This is a contract change only. No door, record store or runtime path ships yet.
