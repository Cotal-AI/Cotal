`cotal update --self` and the daemon's automatic update now work where the package manager's folders are group-writable, as the Homebrew Node's `lib` is and as npm under a umask of 0002 leaves the package, and where Node before 24.22 copied the new version with group-writable folders. 0.164.16 and 0.164.17 refused there with `unprotected execution entry`, and each automatic attempt left a 66 MB folder behind. Those two versions cannot update themselves on such a machine: run the installer again or `npm install -g cotal-ai@latest` once. Their automatic attempts now print that instruction and remove the leftover folders. Staging folders are removed after every update. Connector reconciliation no longer refuses its own staging folder under a umask of 0002 on a machine without `getfacl`. The daemon's automatic update now works after an earlier staged update: a 0.164.16 or 0.164.17 daemon that had updated itself once ended every later attempt with `staged update requires an installed npm or pnpm package` and kept showing `updating to <version>`; run `cotal update --self` once on such a machine. An updater that ends without recording an outcome is now counted as a failure and its last lines are shown in `cotal daemon status`. `cotal update --self` works again in a Linux session without `XDG_RUNTIME_DIR` when no daemon is running, and a refused staged update no longer leaves its copy of the new version behind.
